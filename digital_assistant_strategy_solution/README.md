# 数字副店长上游策略多智能体方案

> 对齐现有「数字副店长工作台」交互原型，参考 `qly门店执行和复盘优化` 的文档组织方式，将“药品匹配、活动草案、库存预警”从原型页面完善为可讲述、可答辩、可开发拆解的多智能体方案。

## 1. 项目背景

医药零售门店已经沉淀了大量会员、交易、库存与活动数据，但在实际经营中仍存在三个断点：

1. **会员需求与药品推荐断点**：知道会员标签，却难以自动判断本轮活动适合推荐哪些品类。
2. **策略生成与人工审核断点**：活动配置依赖人工经验，券包、渠道、时间和门店动作缺少统一生成逻辑。
3. **活动策略与库存承接断点**：活动发布前没有充分评估库存风险，导致触达有效但门店缺货、承接不足。

本方案希望在“门店执行 Agent”和“复盘优化 Agent”之前，补齐上游策略链路：

```text
机会信号 → 会员洞察 → 药品匹配 → 活动草案 → 库存预警 → 门店执行 → 活动复盘 → 策略模板
```

## 2. 方案目标

- 把“会员标签”转化为“可运营的推荐品类”。
- 把“经营机会”转化为“可审核、可发布的活动草案”。
- 把“活动计划”提前校验为“门店库存可承接的执行方案”。
- 与现有门店执行、复盘优化模块形成完整闭环。

## 3. 核心业务场景

- 换季降温触发感冒、呼吸道、慢病关怀活动。
- 慢病会员临近复购窗口时生成复购提醒活动。
- 舆情或区域流感热点触发健康提醒与品类推荐。
- 沉睡会员召回时生成差异化券包与触达策略。
- 活动发布前识别高风险 SKU，并生成补货建议或替代品类。

## 4. 多 Agent 总体架构

本方案采用“主控 Agent + 三个核心专项 Agent + 已有下游 Agent”协同模式。

| Agent | 主要作用 | 在方案中的位置 |
| --- | --- | --- |
| 信号感知 Agent | 发现天气、舆情、季节、复购等机会信号 | 上游触发 |
| 会员洞察 Agent | 生成目标人群包与推荐理由 | 上游输入 |
| 药品匹配 Agent | 根据人群、场景、库存和合规边界推荐品类/SKU | 本方案核心 1 |
| 活动草案 Agent | 生成券包、渠道、触达时间、门店动作与审核流 | 本方案核心 2 |
| 库存预警 Agent | 预测缺货风险，生成补货建议、替代品与预约单 | 本方案核心 3 |
| 门店执行 Agent | 将已发布方案拆解为店长/店员任务 | 下游承接 |
| 复盘优化 Agent | 分析结果并沉淀模板 | 下游反馈 |

## 5. 三个核心 Agent 一句话定位

- **药品匹配 Agent**：把“会员需求与经营信号”翻译成“合规可推荐的品类清单”。
- **活动草案 Agent**：把“推荐品类与目标人群”翻译成“可审核发布的活动方案”。
- **库存预警 Agent**：把“活动需求”翻译成“门店能不能接、怎么补货、是否需要替代品”。

## 6. 方案亮点

1. **不是单点推荐，而是策略链路**：从品类匹配到活动草案，再到库存承接。
2. **不是黑箱生成，而是可解释决策**：每个推荐都有触发原因、人群依据、历史数据与合规提示。
3. **不是直接自动发布，而是保留人工审核闸门**：总部运营可调整券包、人群、时间与门店动作。
4. **不是只做活动前策略，而是接入执行和复盘闭环**：活动执行结果会回流到策略模板。

## 9. 交付口径

对老师或客户可这样概括：

> 本方案不是简单做一个活动配置页面，而是把医药零售门店的主动经营过程拆成多个可协作的智能体。系统先识别经营机会，再判断哪些会员值得触达、哪些品类适合推荐、活动券包怎样设计、门店库存能否承接，最后由门店执行并回传数据复盘。这样可以把“人工拍脑袋做活动”升级为“数据驱动、合规审核、门店可执行、结果可复用”的数字副店长闭环。
