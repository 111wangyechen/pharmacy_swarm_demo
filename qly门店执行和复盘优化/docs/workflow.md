# 业务闭环流程说明

## 1. 业务场景入口

系统可从以下场景进入：

- 慢病管理
- 降温健康
- 舆情流感
- 会员召回
- 库存补货

## 2. 端到端流程

1. 信号感知 Agent 识别经营机会或风险；
2. 主控 Agent 判断是否需要发起活动；
3. 会员洞察 Agent、药品匹配 Agent、库存履约 Agent 提供决策依据；
4. 活动策略 Agent 生成活动方案；
5. 门店执行 Agent 将方案拆解成店长和店员任务；
6. 门店完成承接、服务、核销和反馈；
7. 复盘优化 Agent 分析结果，形成优化建议；
8. 优化建议回传主控 Agent，支持下一轮推荐。

## 3. 用户侧体验

用户侧并不需要直接面对复杂的多 Agent 协作，而是通过工作台完成核心动作：

```text
工作台 → 会员运营 → 活动管理 → 门店执行 → 复盘分析
```

这样的设计有两个好处：

1. 对门店人员来说，界面仍然是熟悉的业务流程，不需要理解底层 Agent 细节；
2. 对系统来说，后端可以持续增强智能能力，而不破坏前台使用习惯。

## 4. 为什么需要闭环

如果系统只做到活动生成，那么它更像一个“建议器”；  
如果系统能够继续追踪执行、分析结果、沉淀模板，它才真正具备持续改进能力。

因此，本项目最核心的价值不是单个 Agent 有多聪明，而是各 Agent 能否共同完成：

```text
发现机会 → 做出决策 → 推动执行 → 判断结果 → 改进下一轮
```
