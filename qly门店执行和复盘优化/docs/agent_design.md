# 总体 Agent 设计

## 1. 总体架构说明

本项目围绕医药零售门店的主动经营需求，设计一套多 Agent 协同方案。系统不是单纯生成活动文案，而是围绕真实业务链路，将天气、舆情、会员、药品、库存和门店执行数据连接起来，形成完整闭环。

整体上可以分为六个阶段：

1. **感知**：识别天气变化、舆情热点、复购周期等信号。
2. **洞察**：分析会员、药品和库存情况。
3. **决策**：判断是否需要发起活动，并确定目标和优先级。
4. **触达**：生成活动策略、券包和沟通建议。
5. **履约**：由门店承接执行，并结合库存情况完成服务。
6. **复盘**：评估效果，沉淀经验，优化下一轮策略。

## 2. 多 Agent 协同关系

| Agent | 主要作用 |
| --- | --- |
| 信号感知 Agent | 发现外部和内部经营信号 |
| 主控 Agent | 统筹任务、判断优先级、分配协作 |
| 会员洞察 Agent | 筛选目标会员并识别需求 |
| 药品匹配 Agent | 提供推荐药品与合规提醒 |
| 活动策略 Agent | 设计活动方案、券包与触达方式 |
| 库存履约 Agent | 评估库存支持能力和补货需求 |
| 门店执行 Agent | 将策略转化为门店任务 |
| 复盘优化 Agent | 评估效果并沉淀优化建议 |

这些 Agent 之间不是彼此孤立的模块，而是围绕同一业务目标分工协作。主控 Agent 负责调度，专项 Agent 分别提供判断依据和执行支持。

## 3. 门店执行 Agent 与复盘优化 Agent 的位置

在整体流程中：

- **门店执行 Agent** 位于“策略生成之后、门店落地之前”，负责把总部方案真正变成店长和店员可以执行的动作。
- **复盘优化 Agent** 位于“活动完成之后”，负责判断执行效果，并识别问题出在策略、会员、门店还是库存。

如果没有门店执行 Agent，系统容易停留在“策略生成”；如果没有复盘优化 Agent，系统又会停留在“一次性执行”。这两个 Agent 共同保证方案能够真正落地，并且越做越好。

## 4. 二者之间的数据闭环关系

门店执行 Agent 会持续产生以下数据：

- 店长是否确认任务；
- 店员是否完成触达；
- 会员是否到店、是否核销；
- 门店是否出现缺货、承接不足等异常；
- 一线人员的反馈意见。

复盘优化 Agent 会基于这些数据进一步判断：

- 是策略本身不够好，还是执行不到位；
- 哪类会员更容易转化；
- 哪些门店承接效果更好；
- 哪些经验值得沉淀为下一轮模板。

因此，两者之间形成了一个很关键的闭环：

```text
策略生成 → 门店执行 → 数据回传 → 复盘分析 → 优化建议 → 下一轮策略
```

门店执行 Agent 负责把策略落到门店，复盘优化 Agent 负责判断执行效果并优化下一轮策略。二者共同保证系统不是停留在“策略生成”，而是真正形成“执行—反馈—优化”的业务闭环。
